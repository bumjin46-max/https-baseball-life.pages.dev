# 야구 인생 — MVP 개발 노트

`baseball-life.html` 파일 하나로 동작합니다. 더블클릭해서 브라우저로 열면 바로 플레이됩니다. 서버, 빌드, 설치 필요 없음.

---

## 1. 지금 구현된 것

새 선수 → 포지션 선택 → 능력치 생성 → 2026 시즌 → 훈련 → 스토리 이벤트 → 결정적 순간 선택 → 반기 경기 시뮬레이션 → 순위/포스트시즌 → 시즌 결산 → 특성 획득 → 국가대표 → FA → 은퇴 판단 → 다음 시즌 → 최종 엔딩 → 명예의 전당.

## 2. 아직 없는 것

- 가상 선수 데이터베이스(리그 전체 선수). 지금은 리그 1위 기록을 확률분포로 생성합니다
- 트레이드, 2군 강등/콜업 연출, 구단별 전용 이벤트
- 특성 조합 전용 스토리(시너지는 수치로만 반영)
- 월 단위 일정, 경기 단위 로그
- 이벤트 100종·특성 추가분 (구조는 열려 있음)

## 3. 실행 방법

`baseball-life.html`을 브라우저에서 열면 끝입니다. 진행 상황은 자동 저장되며, 창을 닫았다 열면 **이어하기**로 복귀합니다. 은퇴한 선수는 명예의 전당에 통산 WAR 순으로 쌓입니다.

## 4. 파일 구조

한 파일 안에서 레이어를 나눠 두었습니다. 주석 번호가 곧 모듈 경계입니다.

```
[1] UTIL          난수, 저장소
[2]~[8] DATA      구단 / 능력치 정의 / 특성 / 훈련 / 이벤트 / 결정적 순간 / 엔딩
[9]~[12] ENGINE   선수 생성·성장 / 시즌 시뮬레이션 / 특성 판정 / 오프시즌·은퇴·엔딩
[13]~[16] UI      렌더링 / 페이즈 진행 / 저장
```

React + TypeScript + Vite로 옮길 때는 그대로 아래로 대응됩니다.

```
[2]~[8]  → src/data/{teams,traits,events,moments,endings,trainings}.ts
[9]~[12] → src/engine/{gameEngine,seasonEngine,matchEngine,traitEngine,endingEngine}.ts
[13]~[16]→ src/components/* + src/state
```

## 5. 콘텐츠 추가하는 법

엔진은 건드리지 않습니다. 배열에 객체 하나만 넣으면 됩니다.

**특성 추가** — `TRAITS` 배열에:

```js
T('끝판대장','전설','pitcher','9회 등판 시 능력 대폭 상승',
  {clutch:14, era:-.3},
  { prob:(p,s)=> s.sv>=30 ? .5 : 0,              // 시즌 종료 시 획득 확률
    evolve:{ to:'수호신', cond:p=>p.tot.sv>=250 } // 진화 조건
  })
```
`eff` 키는 엔진이 읽는 수치입니다: `train, staminaCost, injury, clutch, big, contact, power, eye, speed, defense, throw, ctrl, stuff, velo, k9, bb, so, ip, era, win, fan, lead, teamB, aging, lateGrow, potential, rehab`.

**이벤트 추가** — `EVENTS` 배열에:

```js
EV({ id:'E_2033_HOME', w:6, once:1,
  when:p => p.age>=30 && p.flags.includes('captain'),
  title:'후배들이 찾아왔다',
  text:p => `라커룸에 후배 셋이 서 있다.\n"선배님, 올해는 저희가 하겠습니다."`,
  choices:[
    { t:'맡긴다', s:'리더십 ↑ 개인 성적 ↓',
      run:p => { tend(p,{leadership:10}); return ['그는 한 발 물러섰다.']; } }
  ]})
```
조건에 쓸 수 있는 값: `p.age p.year p.st.* p.pot p.tend.* p.rel.* p.flags p.traits p.awards.* p.season.* p.injuries p.rival.bond p.fanRating`.
결과에 쓸 수 있는 함수: `grow(p,{컨택:…})` `tend(p,{…})` `rel(p,'manager',±)` `flag(p,'이름')` `p.fatigue ±` `p.clutchBonus ±`.

**결정적 순간 추가** — `MOMENTS` 배열. `kind:'aggr'|'patient'|'safe'` 만 지정하면 성공 확률·보상 계산은 엔진이 합니다.

**엔딩 추가** — `ENDINGS` 배열은 **위에서부터 먼저 맞는 것**이 채택되므로, 희귀한 엔딩일수록 위에 둡니다.

## 6. 테스트 방법

개발 중 90회 자동 플레이(무작위 선택)로 밸런스를 검증했습니다. 같은 방식으로 콘솔에서 돌릴 수 있습니다.

```js
// 브라우저 콘솔에서: 무작위 선택으로 커리어 한 번 끝까지 진행
startGame('테스트','batter');
while (G.screen === 'game') {
  G.ui && G.ui.choices ? choose(Math.floor(Math.random()*G.ui.choices.length)) : advance();
}
console.log(G.p.tot, G.p.ending.title, G.p.traits);
```

현재 무작위 플레이 기준 통산 WAR 중앙값 23, 상위 25% 45, 엔딩 분포는 13종에 고르게 퍼집니다. 특정 엔딩이 30%를 넘으면 그 조건이 너무 헐겁다는 신호입니다.
